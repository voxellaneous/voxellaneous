# Multiplayer Protocol (Authoritative Server)

This document describes the current authoritative multiplayer protocol built on Geckos.io.

## Topology
- Transport: WebRTC DataChannel via Geckos.io.
- Model: **Authoritative server**. Clients send inputs; server simulates and broadcasts snapshots.
- Channels:
  - `raw` channel: binary messages (inputs + snapshots).
  - Event channel: used only for non-binary messages (welcome).

## Connection lifecycle
1) Client connects to server (Geckos).
2) Server sends `welcome` with assigned numeric `id`.
3) Client starts sending binary `UserCmd` (raw) every frame.
4) Server sends binary `WorldSnapshot` (raw) at the network tick rate.

## Message types

### `welcome` (server -> client)
JSON event message:
```
{ "id": <number> }
```

### `UserCmd` (client -> server, raw)
Binary payload, 13 bytes. See `docs/NETCODE.md` for layout and bitmask.

### `WorldSnapshot` (server -> client, raw)
Binary payload with fixed-size entities. See `docs/NETCODE.md` for layout and quantization.

## Timing
- Server simulation: fixed timestep.
- Server snapshot tick: fixed interval (configured in server loop).
- Client rendering: interpolates between snapshots.

## Notes
- IDs are numeric (`u32`) and generated by the server.
- All binary data is little-endian.
- `docs/NETCODE.md` is the single source of truth for formats.
